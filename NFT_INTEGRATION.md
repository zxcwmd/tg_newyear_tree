# 🎁 NFT-подарки на открытке — как это работает и как включить настоящий блокчейн

Сейчас в проекте **уже работает локальный реестр подарков**: друг может прикрепить NFT-подарок
к твоей открытке, он появляется карточкой на полке у подножия ёлки в
`/api/final-image` и в мини-приложении. Всё готово к тому, чтобы заменить «номер токена
в базе» на настоящий токен в блокчейне.

---

## 1. Что уже есть

| Слой | Что сделано | Файл |
|---|---|---|
| Каталог коллекции | 5 подарков с редкостью и тиражом (`NFT_GIFTS`) | `database.py` |
| Реестр подарков | Таблица `tree_gifts`: `token_id`, `from_user_id`, `to_user_id`, `message`, `wallet` | `database.py` |
| API | `GET /api/nft-gifts/catalog`, `POST /api/nft-gifts`, `GET /api/nft-gifts/{chat_id}` | `webapp/app.py` |
| Открытка | Полка с карточками: эмодзи, название, «от кого», сообщение, номер токена | `tree_image.py` → `_draw_nft_gifts` |
| Мини-приложение | Живое превью открытки, чипы подарков, скачивание и шаринг | `webapp/static/app.js` |

Проверка:

```bash
curl -X POST http://localhost:8000/api/nft-gifts \
  -H 'Content-Type: application/json' \
  -d '{"to_user_id": 502, "token_id": 3, "message": "С Новым годом!",
       "user": {"id": 501, "first_name": "Аня"}}'
```

## 2. Три способа сделать подарки «настоящими» NFT

### Вариант A — Telegram NFT Gifts (самый простой для Telegram-бота) ⭐ рекомендую

У Telegram есть коллекционные подарки (Unique Gifts): их можно отправлять в чат, они
становятся NFT в сети TON и имеют адрес вида `EQC…` + номер экземпляра.

**Как реализовать:**

1. Бот создаёт/покупает коллекцию подарков (или использует готовую коллекцию через
   Bot API: `getAvailableGifts`, `sendGift`).
2. Пользователь дарит подарок другу **через бота**, а не через Mini App:
   - Mini App присылает `POST /api/nft-gifts` с `token_id`;
   - сервер вызывает `bot.send_gift(user_id=<друг>, gift_id=<id>)`;
   - в ответ приходит `owned_gift_id` / `nft_address`.
3. Эти данные записываются в `tree_gifts`: добавляем колонки `nft_address`,
   `gift_slug`, `owned_gift_id` (миграция уже подготовлена структурно — достаточно
   `ALTER TABLE`).
4. На открытке рисуем «настоящий» титул: адрес сокращаем (`EQC…7f2a`), номер экземпляра
   берём из NFT.

```python
# bot.py — набросок
@dp.message(Command("gift"))
async def cmd_gift(message: Message):
    await message.answer_gift(...)  # или bot.send_gift(...)
```

**Плюсы:** пользователю не нужен кошелёк, оплата в Stars, подарок реально он-чейн.
**Минусы:** нужен бот с правом отправки подарков и оплата Stars за каждый.

---

### Вариант B — TON Connect + собственный смарт-контракт (полный контроль)

**Как реализовать:**

1. **Контракт коллекции** (FunC/Tact) по стандарту TEP-62/TEP-64:
   - `collection_address`, у каждого подарка свой `item_index` = `token_id`;
   - метаданные (название, эмодзи, картинка) лежат в IPFS/Arweave.
2. **Минт**: сервер (или пользователь) вызывает `mint(to=<кошелёк друга>, index=<token_id>)`.
   - Газ ~0.05 TON, можно спонсировать с серверного кошелька.
3. **Кошелёк в Mini App**: подключаем `@tonconnect/ui` (в `index.html`):
   ```html
   <script src="https://unpkg.com/@tonconnect/ui@latest/dist/tonconnect-ui.min.js"></script>
   ```
   и `new TONConnectUI({ manifestUrl: "https://<домен>/tonconnect-manifest.json" })`.
   Кнопка «Подключить кошелёк» → получаем адрес.
4. **Прикрепление к открытке**: после успешного минта отправляем в
   `POST /api/nft-gifts` уже с `wallet` и `tx_hash`; сервер проверяет транзакцию
   через TON API (`https://tonapi.io/v2/...`) и только тогда пишет подарок в БД.
5. **Проверка владения** при показе открытки: раз в N минут сверяем `owner` NFT
   с `to_user_id`; если подарок перепродан — он остаётся «историей» на открытке,
   но помечается как переданный дальше.

**Плюсы:** настоящая собственность, можно продавать на маркетплейсах (Getgems и т.п.).
**Минусы:** нужен аудит контракта, газ, кошелёк у пользователя, юридические нюансы.

---

### Вариант C — сторонний NFT-сервис (без своего контракта)

Например, коллекции на **Getgems / Tonkeeper / TonAPI**: минтим через их API
(`POST /v2/nft/...`), либо просто выдаём **подписанный сертификат** (JWT + картинка),
который хранится в БД и валидируется подписью. Это «NFT-лайт»: без блокчейна,
но с проверяемым сертификатом.

**Когда подходит:** нужен быстрый запуск без крипто-кошельков и газа.

## 3. Что менять в коде (общий чек-лист)

1. **Миграция** `tree_gifts`: `ALTER TABLE ... ADD COLUMN nft_address TEXT DEFAULT ''`,
   `tx_hash`, `collection`.
2. **`database.add_nft_gift(...)`** — принять `nft_address`/`tx_hash`, сохранить.
3. **`webapp/app.py`**:
   - `POST /api/nft-gifts` → сначала минтинг (A/B/C), затем запись в БД;
   - новый `GET /api/nft-gifts/verify/{gift_id}` — перепроверка владельца через TON API.
4. **`tree_image._draw_nft_gifts`** — добавить сокращённый адрес (`EQC…7f2a`)
   и бейдж редкости (common/rare/epic/legendary/mythic).
5. **Mini App** — кнопка «🎁 Прикрепить NFT-подарок», выбор из каталога,
   ввод имени друга, отправка.
6. **Безопасность**: проверять, что `token_id` уникален на получателя
   (одна копия = один экземпляр), ограничить число подарков на ёлку (сейчас 4 в открытке),
   валидировать `init_data` (уже реализовано в `resolve_user`).

## 4. Что я могу сделать прямо сейчас vs что требует ключей

Могу самостоятельно (без ключей/аккаунтов):

- ✅ довести UI «Прикрепить NFT-подарок» (модалка, выбор из каталога, отправка другу);
- ✅ добавить бейджи редкости и сокращённые адреса на открытку;
- ✅ подготовить миграции и заглушку `mint_gift()` с флагом `enabled=False`;
- ✅ написать юнит-тесты на подарки и приватность.

Требует ваших данных (не делаю без них):

- ⛔ `BOT_TOKEN` с правом отправки Unique Gifts + оплата Stars;
- ⛔ адрес коллекции / контракт в TON и кошелёк для минта;
- ⛔ API-ключ TON API (tonapi.io / toncenter);
- ⛔ `tonconnect-manifest.json` на вашем домене.

Как только дадите эти данные — подключение занимает один PR: заменить заглушку
`mint_gift()` на реальную отправку и включить кнопку в интерфейсе.
