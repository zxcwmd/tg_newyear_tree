# Telegram-подарки и NFT на ёлке

Документ описывает, как игрок прикрепляет **свои реальные подарки из Telegram** (обычные
`regular` и уникальные `unique`/NFT) к ёлке, и как это устроено внутри.

> Раньше здесь был план «минта» внутриигровых NFT. Концепция изменена: игрок показывает на
> ёлке подарки, которые у него уже есть в Telegram — мы ничего не минтим, не передаём и не
> выводим из его аккаунта.

---

## 1. Что видит игрок

1. В приложении нажимает **«🎁 Подарки на ёлке»** (кнопка на панели открытки).
2. Открывается вкладка **«💎 Мои Telegram-подарки»** — список его подарков из Telegram:
   эмодзи, название, номер NFT, от кого получен.
3. Нажимает на подарок → он прикрепляется к его ёлке (повторное нажатие — снять).
4. Подарок появляется карточкой на полке у подножия ёлки: в превью в приложении
   и на итоговой открытке (`/api/final-image/...`).
5. Вторая вкладка **«🎮 Подарить внутри игры»** осталась для внутриигровых NFT-подарков
   друзьям — это отдельная механика, она не заменяет Telegram-подарки.

Подарок **не передаётся** и **не минтится**: игрок остаётся владельцем, а на ёлке
отображается карточка-«сертификат» (название, номер, подпись).

---

## 2. Как это работает технически

### 2.1. Получение подарков игрока

Telegram Bot API **9.3+** (31.12.2025) даёт метод
[`getUserGifts`](https://core.telegram.org/bots/api#getusergifts):

| Параметр | Значение |
| --- | --- |
| `user_id` | ID игрока (приходит из `initData` Mini App) — обязательный |
| `limit` | 1–100, по умолчанию 100 |
| `offset` | курсор для следующей страницы (`next_offset`) |
| `exclude_unique` / `exclude_from_blockchain` / … | фильтры, нам не нужны |

Ответ — `OwnedGifts { total_count, gifts[], next_offset }`, где каждый элемент это
`OwnedGiftRegular` или `OwnedGiftUnique`:

* `OwnedGiftUnique.gift` — `UniqueGift`: `name` (оно же в ссылке `t.me/nft/<name>`),
  `number`, `model`, `symbol`, `backdrop`, `is_from_blockchain`;
* `OwnedGiftRegular.gift` — `Gift`: `id`, `sticker`, `star_count`;
* общие: `send_date`, `sender_user`, `text`.

⚠️ Важное ограничение: **`owned_gift_id` приходит только для бизнес-аккаунтов**. Поэтому
для обычных игроков мы собираем стабильный ключ сами:

* unique → `nft:<name>` (имя NFT глобально уникально);
* regular → `reg:<gift.id>:<send_date>:<sender_id>`.

Ключ детерминированный, поэтому повторные запросы не плодят дубли и проверка владения
работает без business-подключения.

### 2.2. Проверка владения

`POST /api/telegram-gifts/attach` не верит клиенту: сервер заново вызывает
`getUserGifts` и ищет подарок с таким ключом среди подарков **этого** `user_id`.
Если не нашёл — `403`: прикрепить чужой подарок или подделку нельзя.

### 2.3. Хранение

Таблица `attached_gifts`:

| Поле | Смысл |
| --- | --- |
| `tree_id` | ёлка (у каждого игрока личная, есть и командные) |
| `user_id` | владелец подарка |
| `owned_gift_id` | стабильный ключ из п. 2.1 |
| `kind` | `regular` / `unique` |
| `is_nft` | `unique` = настоящий NFT в TON |
| `slug`, `title`, `subtitle`, `emoji` | для карточки в UI и на открытке |
| `sender_name`, `number` | от кого и номер NFT |
| `message` | подпись игрока на открытке |

Уникальность `(tree_id, owned_gift_id)` — один подарок нельзя прикрепить дважды,
а повторное прикрепление обновляет подпись.

### 2.4. API

| Метод | Что делает |
| --- | --- |
| `GET /api/telegram-gifts?user_id=…` | список подарков игрока + `attached`-флаги |
| `POST /api/telegram-gifts/attach` | прикрепить (с проверкой владения) |
| `POST /api/telegram-gifts/detach` | снять свой подарок |
| `GET /api/tree/{id}` | отдаёт `telegram_gifts`, `telegram_gifts_enabled` |
| `GET /api/final-image/{id}` | рисует прикреплённые подарки на открытке |

### 2.5. Отрисовка

`tree_image._draw_nft_gifts` рисует до 4 карточек, остальное — «ещё +N».
У каждой карточки медальон, название, «от …», подпись игрока и бейдж
(`NFT №42` / `Telegram`).

Эмодзи рисуются настоящим эмодзи-шрифтом, если он есть на сервере. В контейнере без
Noto Color Emoji включён векторный фолбэк: ромб для NFT, сердечко, звезда, снежинка,
ёлка, подарок и т.д. — поэтому открытка не содержит «тофу»-квадратов.

## 3. Если Telegram недоступен

`GET /api/telegram-gifts` никогда не отдаёт 500 — при ошибке возвращает
`{ok: false, available: false, reason, fallback: "manual_link"}`. В этом случае
модалка показывает поле для ссылки `t.me/nft/…` и объясняет, что делать.
Владение всё равно проверяется сервером при прикреплении.

Дополнительные фолбэки, которые можно включить позже:

* **по ссылке** — игрок присылает боту сообщение с подарком/ссылкой, бот сохраняет
  подарок и привязывает его по `marketplace`/`getUniqueGift`;
* **TON-кошелёк** — для NFT, выведенных в TON: проверка владельца через `tonapi.io`
  (нужен `TON_API_KEY`), полезно, когда подарок уже не виден в Telegram-профиле;
* **кэш** — периодическая перепроверка прикреплённых подарков (раз в N часов) и
  скрытие карточки, если игрок больше не владеет подарком
  (`is_hidden = 1`, без удаления записи).

## 4. Флаги окружения

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `TELEGRAM_GIFTS_ENABLED` | `1` | выключает вкладку Telegram-подарков целиком |
| `TELEGRAM_GIFTS_LIMIT` | `24` | сколько последних подарков запрашивать |
| `TELEGRAM_API_BASE` | `https://api.telegram.org` | адрес Bot API (прокси/тесты) |
| `NFT_MINT_ENABLED` | `0` | минт внутриигровых NFT (отдельная механика, выключен) |
| `NFT_COLLECTION_ADDRESS`, `TON_API_KEY` | — | для минта/проверки TON-владения |

`BOT_TOKEN` обязателен: запросы к `getUserGifts` идут от имени бота.

---

## 5. Что нужно от вас, чтобы включить в бою

1. `BOT_TOKEN` рабочего бота (без него список подарков не получить).
2. Mini App открывается внутри Telegram — `user_id` берётся из `initData`.
3. Проверить на реальном аккаунте с подарками: обычный подарок, апгрейженный NFT,
   NFT, пришедший из блокчейна.
4. Если хочется «живых» картинок подарков вместо эмодзи — установить на сервер
   `fonts-noto-color-emoji` (сейчас есть векторный фолбэк, он уже выглядит аккуратно).
